# Diagnostic-only active-set membership hotfix

Historical Docker verify code unions a hard-coded list of legacy set names.
The running nft actions may instead write `f2b-f2b-*`, `addr-set-*` or
`addr6-set-*` names. Reading old unused sets can report false Docker misses even
when all active jail bans are present. A successful count-only sync check also
does not prove membership equality. This diagnostic defect is separate from the
[port persistence hotfix](PORT-PERSISTENCE-HOTFIX.md).

## What the new checker means

- Inventory comes from the actual active Fail2Ban jails, not a fixed list of 13.
- Set references come from **loaded action properties** through the Fail2Ban
  socket, including family-specific names. A pending disk edit is not silently
  mistaken for the running action. No guessed legacy aliases are used.
- Compare exact IPv4/IPv6 members per effective set and the union of active jail
  bans against both Docker sets. Shared effective sets aggregate their owners.
- Prefixes/ranges are normalized symbolically, including large IPv6 intervals;
  they are not expanded into potentially enormous address lists.
- Missing sets are accepted only for a zero-ban family whose loaded action can
  lazily create them. Missing static sets, API/nft failures, malformed responses,
  wrong families, equal-count wrong members and actual Docker extras/misses fail
  nonzero. A changing ban snapshot requests a read-only retry, not forced sync.

Sets unused by **loaded jail actions** are excluded from the expected Docker
union. This does **not** mean they are unreferenced by every firewall rule or safe
to delete. PASS covers active-action membership and Docker union, not every orphan
rule, log/filter coverage, external connectivity or packet-drop enforcement.

## Staged deployment dependencies and scope

Use the exact reviewed repository commit supplied with successful CI. Source
preflight needs only Python's standard library, `bash`, `nft`, and the distro
Fail2Ban Python `CSocket` module. No packages are installed by the tool. The
standard Fail2Ban socket is `/var/run/fail2ban/fail2ban.sock`; custom socket setups
require separate review. Runtime must permit root read access to that socket/nft.

The standalone `/usr/local/libexec/f2b-diagnostic-membership.py` is generated by
static extraction of the canonical read-only functions from the current verifier.
It contains only read operations and supports only `--sync-check` and
`--docker-check`. It has **no installed reconciler, updater or old runtime-verifier
dependency**. Those existing production helpers are not overwritten.

Deployment first stages/compiles the checker and patches only `f2b_sync_check` and
`f2b_docker_verify`. Published legacy counter/union function shapes, their local
effective-name fixes, current canonical forwarding functions and already-patched
functions are supported. Unknown diagnostic bodies are refused for review.
All bytes outside those two functions are preserved, including local changes and
the port hotfix. Local filters, jail policy/whitelists, bans, persistence files,
Docker, CrowdSec, cron and databases are untouched. No services reload or restart.

## First preflight, then explicit code apply

From the reviewed checkout's `releases/v0.34`:

```sh
sudo python3 scripts/install-diagnostic-hotfix.py
```

This is code/dependency staging preflight, **not a membership PASS**. It creates
only private temporary candidates and an advisory upgrade lock; no installed code
or runtime configuration changes. It verifies target ownership, dependencies,
helper compilation, wrapper Bash syntax and exact non-diagnostic preservation.

Only after preflight PASS and operator approval:

```sh
sudo python3 scripts/install-diagnostic-hotfix.py --apply
```

Apply makes a root-private code backup and checksum/absence manifest, installs
the standalone checker **before** redirecting the two wrapper functions, checks
installed bytes, and restores original code on failure. A missing libexec directory
is created on apply only. An existing differing standalone checker is preserved
and refused. No full manager/release/profile upgrade is performed.

## Read-only checks after deployment

```sh
sudo f2b sync check
sudo f2b docker verify
# Or directly, independent of other old wrapper diagnostic/reporting functions:
sudo python3 /usr/local/libexec/f2b-diagnostic-membership.py --sync-check
sudo python3 /usr/local/libexec/f2b-diagnostic-membership.py --docker-check
```

A mismatch prints the affected set and expected/actual counts, without dumping
operator IP lists. Equal counts still fail if members differ. **Do not** respond
with `sync force`, delete orphan sets, remove bans, flush anything or reload the
firewall. Keep the state intact and diagnose whether it is a real active-set
discrepancy, legitimate concurrent expiry/ban change, or unsupported action format.
This hotfix never performs that repair automatically.

## Regression boundary

Synthetic unit tests cover stale legacy sets versus loaded aliases, equal counts
with different members, shared address intervals/prefixes, missing/lazy sets and
failed API reads. Private Linux fixtures exercise actual loaded Fail2Ban action
properties, generated-checker deployment/rollback, stale set exclusion, true
mismatch error propagation and unchanged filters/reconciler/port functions.
No production IPs, operator exports or private deployment fingerprints are shipped.
